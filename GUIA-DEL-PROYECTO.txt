1. QUÉ ES ESTE PROYECTO
--------------------------------------------------------------------------
Es un sistema para gestionar las calificaciones y la ASISTENCIA de los
estudiantes, siguiendo el reglamento de la UPE. Tiene dos partes que corren
juntas en el mismo programa:

  - Una PÁGINA WEB (http://localhost:8080) con login y pantallas para
    cargar y consultar todo desde el navegador.
  - Una API REST (las direcciones /api/...) que es la que guarda y
    entrega los datos. La página web la usa por detrás.

Cómo está organizado:
  - Hay CARRERAS (ej.: Informática, Administración, Derecho...).
  - Cada MATERIA pertenece a una carrera y tiene un DOCENTE a cargo.
  - Cada ESTUDIANTE pertenece a una carrera y se INSCRIBE en las materias
    que cursa (solo los inscriptos aparecen en la lista y en la planilla).
  - Un estudiante solo recibe notas de materias de SU carrera.
  - La NOTA de cada materia se forma con 1er parcial + 2do parcial +
    trabajo práctico + examen final = 100 puntos. Cuánto vale cada parte
    lo decide cada materia (por defecto 15 + 15 + 20 + 50).
  - Para rendir el EXAMEN FINAL hace falta un mínimo de ASISTENCIA (70 %
    por defecto).

Quién puede hacer qué (JERARQUÍA):
  - ADMIN (super usuario) .. crea carreras, docentes y materias, y decide
                             qué docente está a cargo de cada materia.
                             Otorga EXONERACIONES de asistencia.
                             Ve y puede hacer todo.
  - DOCENTE ................ trabaja SOLO dentro de las carreras donde tiene
                             materias a cargo:
                             · ve y agrega/edita estudiantes de esas
                               carreras (no puede borrarlos);
                             · en SUS materias: inscribe estudiantes, pasa
                               lista, carga notas y define cuánto vale cada
                               parcial, el trabajo práctico y el final;
                             · no ve estudiantes, materias ni notas de
                               otras carreras.
                             Ejemplo: la profesora de Contabilidad no puede
                             ver ni agregar estudiantes de Informática.
                             Un docente sin materias asignadas no ve nada
                             hasta que el admin le asigne una.
  - ESTUDIANTE ............. ve sus propias notas (desglosadas), su
                             promedio y su asistencia en cada materia
                             (con aviso si está en riesgo de no poder
                             rendir el final).
  Todos tienen "Ajustes" para personalizar los colores de la interfaz,
  cambiar su contraseña y activar la VERIFICACIÓN EN DOS PASOS (código de
  Google Authenticator además de la contraseña).
  Casi todas las pantallas tienen "Exportar" a EXCEL, y el admin tiene
  "Carga masiva" para cargar una carrera entera desde un Excel.
  Todos tienen que iniciar sesión primero; el sistema les da un "token"
  (JWT) que se envía en cada petición para demostrar quiénes son.
  Las reglas las controla el SERVIDOR (no solo la página): aunque alguien
  intente saltarse la interfaz, la API responde 403 (prohibido).

Tecnologías:
  - Java 21 ............... lenguaje de programación
  - Spring Boot 3.5 ....... framework que arma el servidor web
  - Spring Security + JWT . inicio de sesión y permisos por rol
  - Spring Data JPA ....... guarda y lee datos de la base sin escribir SQL
  - PostgreSQL ............ base de datos (corre dentro de Docker)
  - Flyway ................ crea y actualiza las tablas de la base
                            automáticamente al arrancar (migraciones)
  - Lombok ................ genera getters/setters/constructores automáticamente
  - Maven ................. descarga librerías y compila (se usa mvnw.cmd,
                            no hace falta instalarlo)

2. CÓMO PROBARLO RÁPIDO (DOBLE CLIC)
--------------------------------------------------------------------------
El sistema tiene DOS partes que se encienden por separado:
  - BASE DE DATOS: PostgreSQL, corre dentro de Docker. Guarda todo.
  - BACKEND: el programa Java. Sirve la página web y la API en
             http://localhost:8080. Necesita la base de datos encendida.

LO MÁS FÁCIL: abrir la carpeta del proyecto en el Explorador de archivos y

  Paso 1. Abrir Docker Desktop y esperar a que diga "Engine running".

  Paso 2. Doble clic en  iniciar-todo.cmd
          Verifica la computadora, enciende la base de datos y el backend.
          La PRIMERA vez tarda varios minutos (descarga librerías).
          Cuando está listo aparece
              Started SeguimientoAcademicoApplication
          y SE ABRE SOLO EL NAVEGADOR en http://localhost:8080
          NO cerrar esa ventana mientras se usa el sistema.
          Para apagarlo: Ctrl + C dentro de la ventana.

  Paso 3. En el navegador, ingresar con un usuario de la tabla de abajo
          (ver "CÓMO USAR LA PÁGINA WEB" más abajo).

O doble clic en  MENU.cmd  que muestra todas las opciones con números:

    INICIAR    1  Iniciar TODO (base de datos + backend + página web)
               2  Iniciar solo la base de datos
               3  Iniciar solo el backend
               4  Abrir la página web
    REVISAR    5  Ver estado (qué está encendido)
               6  Verificar requisitos de la computadora
               7  Probar la API
               8  Ejecutar los tests automáticos
    DETENER    9  Detener el backend
              10  Detener la base de datos
              11  Detener TODO
              12  BORRAR la base de datos (empezar de cero, pide confirmación)

Cada opción también tiene su propio archivo en la carpeta  comandos\ :

  verificar-requisitos.cmd .. qué tiene la PC y qué le falta (con links
                              de descarga de cada cosa).
  iniciar-base-de-datos.cmd . enciende SOLO PostgreSQL (Docker).
  iniciar-backend.cmd ....... enciende SOLO el backend. Si la base está
                              apagada avisa y no arranca.
  abrir-pagina-web.cmd ...... abre http://localhost:8080 (si el backend
                              está encendido).
  estado.cmd ................ muestra Docker / base de datos / backend:
                              encendido o apagado.
  probar-api.cmd ............ prueba la API sin navegador: login de
                              docente, registra una nota, login de
                              estudiante, muestra sus notas y comprueba
                              que un estudiante NO pueda registrar notas.
                              Termina con "La API funciona correctamente".
  ejecutar-tests.cmd ........ tests automáticos (solo necesita Java).
  detener-backend.cmd ....... apaga el backend.
  detener-base-de-datos.cmd . apaga la base (los datos se conservan).
  detener-todo.cmd .......... apaga las dos cosas.
  borrar-base-de-datos.cmd .. BORRA todos los datos. Hay que escribir
                              BORRAR para confirmar. Al iniciar de nuevo
                              se crea vacía con los datos de ejemplo.

Ejemplo, trabajando por partes:
  comandos\iniciar-base-de-datos.cmd   -> se enciende la base
  comandos\iniciar-backend.cmd         -> se enciende el backend
  comandos\abrir-pagina-web.cmd        -> se abre el navegador
  ... usar el sistema ...
  comandos\detener-todo.cmd            -> se apaga todo

Desde la terminal de VS Code (estando en la carpeta del proyecto):
    .\MENU.cmd
    .\iniciar-todo.cmd
    .\comandos\estado.cmd
    .\comandos\iniciar-backend.cmd      (y así con los demás)

Usuarios de ejemplo (se crean solos la primera vez):
    Usuario      Contraseña      Rol
    admin        admin123        ADMIN (super usuario)
    docente      docente123      DOCENTE (a cargo de las materias INF)
    estudiante   estudiante123   ESTUDIANTE (matrícula 2026-0001, Informática)
    lucia, marcos, ana, diego, sofia   estudiante123   ESTUDIANTES de
                 Informática con asistencia de ejemplo: hay uno habilitado,
                 uno en riesgo, uno no habilitado y uno exonerado.

Datos de ejemplo:
    Carreras: INF Ingeniería en Informática, ADM Administración de Empresas
    Materias: id 1 = INF-101 Programación I
              id 2 = INF-102 Matemática Discreta
              id 3 = INF-201 Base de Datos I
              id 4 = ADM-101 Contabilidad I (sin docente asignado)
    Todas empiezan con los puntajes del reglamento: 15 + 15 + 20 + 50.

CÓMO USAR LA PÁGINA WEB
  Diseño: menú a la izquierda (barra lateral), título de la página arriba
  con el botón principal (ej.: "+ Nuevo estudiante") a la derecha.
  - Los formularios se abren en una ventana emergente.
  - Cada tabla tiene un buscador que filtra mientras se escribe.
  - Antes de borrar algo siempre se pide confirmación.
  - En el celular el menú se abre con el botón ☰ de arriba a la izquierda.
  - La dirección cambia con cada pantalla (ej.: #/notas?materia=3), así que
    se puede recargar, usar "atrás" o guardar la página en favoritos.

  La interfaz tiene MOVIMIENTO: al entrar a cada pantalla los bloques, las
  tarjetas y las filas aparecen en cascada, los números de las tarjetas
  "cuentan" hasta su valor, las barras se llenan desde cero, los botones
  hacen una onda al tocarlos y la fila de la planilla destella en verde al
  guardarse. Si Windows tiene activado "Efectos de animación: desactivado"
  (o el navegador pide menos movimiento), todo eso se apaga solo.

  Entrando como ADMIN (admin / admin123):
  Inicio ...... resumen: carreras, materias, docentes, estudiantes, notas
                cargadas, promedio general y asistencia promedio, más el
                AVANCE de carga de notas de cada materia y las ALERTAS de
                estudiantes en riesgo o no habilitados.
  Notas ....... PLANILLA por materia (ver abajo).
  Asistencia .. pasar lista, ver porcentajes e inscribir (ver abajo).
  Reportes .... asistencia promedio por materia y por carrera, cuántos
                estudiantes hay en cada condición y la lista de alertas.
  Estudiantes . "+ Nuevo estudiante": nombre, matrícula, carrera, usuario y
                contraseña. Filtro por carrera. Editar ✎ / Eliminar 🗑.
  Materias .... "+ Nueva materia": código, nombre, carrera, semestre,
                créditos, DOCENTE A CARGO y, opcionales, ASISTENCIA MÍNIMA
                propia (vacío = la de la carrera) y CLASES PREVISTAS (para
                calcular cuántas faltas le quedan a cada uno).
                Para cambiar el profesor de una materia: Editar y elegir
                otro docente. La columna "Puntajes" muestra cuánto vale cada
                parte de la nota; el ícono 📈 de la fila la cambia (ver
                "PUNTAJES DE CADA MATERIA" abajo).
  Docentes .... "+ Nuevo docente": nombre completo, usuario y contraseña.
                La tabla muestra las materias que tiene a cargo.
  Carreras .... "+ Nueva carrera": código, nombre, DURACIÓN EN SEMESTRES
                (1 a 12) y ASISTENCIA MÍNIMA para el final (70 % si se deja
                vacío). Muestra cuántas materias y estudiantes tiene.
                Botón "Plantilla" en cada fila: descarga su Excel de carga.
  Carga masiva  cargar docentes, materias y estudiantes de una carrera
                desde Excel (ver "CARGA MASIVA POR EXCEL" abajo).
  Exoneraciones exonerar a un estudiante de la asistencia de una materia
                (ver "EXONERACIONES" abajo).
  Usuarios .... crear otros administradores, cambiar la contraseña de
                cualquiera (🔑), Desactivar / Activar cuentas, ver quién
                tiene verificación en dos pasos y "Quitar 2FA" (para quien
                perdió el celular).
  Ajustes ..... apariencia y contraseña propia (ver abajo).

  Orden recomendado para cargar todo desde cero (como admin):
      1) Carreras  2) Docentes  3) Materias (asignando el docente)
  Después cada docente entra con su usuario y hace:
      4) Estudiantes de sus carreras
      5) Inscribirlos en sus materias (Asistencia → pestaña Inscriptos)
      6) (opcional) Ajustar los puntajes de cada materia
      7) Pasar lista en cada clase y cargar las notas

  PLANILLA DE NOTAS (pestaña Notas)
    1. Elegir la materia arriba. Aparecen los estudiantes INSCRIPTOS en esa
       materia, con su nota si ya tienen. Arriba se ve un resumen (carrera,
       docente, cuántos tienen nota, promedio) y el botón "Puntajes" con la
       distribución de la materia.
    2. Cada estudiante tiene 4 casilleros: 1er parcial, 2do parcial,
       trabajo práctico y examen final. El encabezado muestra cuánto vale
       cada uno en ESA materia (ej.: "1er parcial /15"). El TOTAL es la suma
       y la CALIFICACIÓN (1 a 5) aparece recién cuando hay examen final:
         1-59 = 1 (reprobado)   60-69 = 2   70-79 = 3   80-90 = 4   91-100 = 5
    3. Enter baja al mismo casillero del estudiante siguiente (se carga una
       columna entera rápido). Cada fila muestra su estado: Guardada /
       Sin nota / Sin guardar / Valor fuera de rango.
    4. El casillero del EXAMEN FINAL queda bloqueado para quien NO está
       habilitado por asistencia (chip "No habilitado" junto al nombre).
    5. Abajo aparece una barra "N notas sin guardar" con "Guardar cambios"
       y "Descartar". Enter en el último estudiante también guarda.
    6. Para borrar una nota: el ícono 🗑 de su fila.
    Si se intenta salir de la planilla con notas sin guardar, el sistema
    pregunta antes de perderlas. Las notas cargadas antes de que existiera
    el desglose aparecen como "Nota única".

  PUNTAJES DE CADA MATERIA (cuánto vale cada parcial, el TP y el final)
    Lo cambia el DOCENTE A CARGO de la materia o un ADMIN:
      - en Notas, botón "Puntajes 15 + 15 + 20 + 50" del resumen, o
      - en Materias, ícono 📈 de la fila.
    Se abre una ventana con los 4 valores y una barra de colores que muestra
    la proporción mientras se escribe. Reglas:
      - los 4 tienen que sumar 100 (el total se pone verde al llegar);
      - el examen final vale al menos 1 punto; los demás pueden valer 0
        (ej.: una materia sin trabajo práctico: 25 + 25 + 0 + 50);
      - se aprueba siempre con 60 puntos;
      - si ya hay notas cargadas, no se puede achicar una parte por debajo
        de lo que alguien ya sacó (ej.: si un alumno tiene 14 en el 1er
        parcial, ese parcial no puede pasar a valer 10). El sistema avisa
        cuántas notas lo impiden.
    Las materias nuevas empiezan con el reglamento: 15 + 15 + 20 + 50.

  ASISTENCIA (pestaña Asistencia)
    Elegir la materia arriba. Tiene tres pestañas:
    Clases ............. "Nueva clase": fecha y tema. Todos empiezan como
                         PRESENTES; se marca a cada uno P (presente),
                         T (tarde), A (ausente) o J (justificada), con el
                         mouse o con esas teclas. Se puede agregar una
                         observación. Las clases anteriores se pueden
                         abrir, corregir o borrar.
    Asistencia y habilitados  porcentaje de cada estudiante, faltas que le
                         quedan (si la materia tiene clases previstas) y su
                         CONDICIÓN.
    Inscriptos ......... inscribir estudiantes uno por uno o "toda la
                         carrera"; quitar a quien se inscribió por error
                         (no se puede si ya tiene asistencia o notas).
    Cómo se calcula (reglamento UPE):
      - 3 llegadas tarde = 1 ausencia.
      - La ausencia JUSTIFICADA queda registrada pero cuenta como ausencia.
      - Mínimo para rendir el final: 70 % (la carrera o la materia pueden
        tener otro).
      - Condiciones: HABILITADO, EN RIESGO, NO HABILITADO (debajo del
        mínimo) y EXONERADO. "En riesgo" = le quedan 2 faltas o menos (si
        la materia tiene clases previstas) o está a menos de 10 puntos del
        mínimo (si no las tiene).
    Botones de Excel: "Planilla de asistencia" (resumen + una columna por
    clase con P/T/A/J) y "Habilitados para el final".

  EXONERACIONES (solo admin)
    Por causa justificada (enfermedad, trabajo...) un admin puede exonerar
    a un estudiante de la asistencia de una materia: queda HABILITADO para
    el final aunque no llegue al mínimo. Máximo 2 materias por semestre por
    estudiante. Se indica el motivo y queda registrado quién la otorgó.
    Los docentes ven quién está exonerado (chip "Exonerado" en sus listas)
    pero no las pueden dar ni quitar.

  Entrando como DOCENTE: Inicio (resumen y alertas de SUS materias), Notas
  y Asistencia (solo sus materias), Reportes, Estudiantes (solo de sus
  carreras; puede agregar y editar, no eliminar), Mis materias (con el
  botón de puntajes) y Ajustes. Si todavía no tiene materias, aparece un
  aviso para pedírselas al administrador.

  Entrando como ESTUDIANTE:
    Mis notas ...... promedio, materias con nota, aprobadas, mejor nota, y
                     cada materia con sus parciales, TP y final mostrados
                     como "obtenido /máximo" de esa materia (ej.: "12 /15").
    Mi asistencia .. una tarjeta por materia con su porcentaje, el mínimo,
                     las clases dictadas, el detalle de cada clase y si
                     puede rendir el final, con aviso cuando está en riesgo.

  AJUSTES (todos los usuarios)
    Apariencia ... Modo (Oscuro / Claro / Automático según Windows),
                   Color principal (9 colores + uno personalizado a gusto),
                   color de la Barra lateral, Densidad (Cómoda / Compacta)
                   y Tamaño del texto (Normal / Grande).
                   Se aplica al instante y se GUARDA EN LA CUENTA: cada
                   usuario ve sus colores en cualquier computadora.
                   "Restablecer" vuelve al azul y negro original.
    Verificación en dos pasos (ver abajo).
    Mi cuenta .... cambiar la propia contraseña (pide la actual).

  VERIFICACIÓN EN DOS PASOS (Google Authenticator)
    Activar: Ajustes → "Activar con Google Authenticator".
      1. Instalar Google Authenticator en el celular (Play Store / App Store).
      2. En la app: "+" → "Escanear un código QR" y apuntar al QR de la
         pantalla (o cargar a mano la clave que aparece debajo).
      3. Escribir el código de 6 dígitos que muestra la app → "Activar".
    Desde entonces, al ingresar: usuario + contraseña → y después el código
    de 6 dígitos que muestra la app en ese momento (cambia cada 30 s).
    - Tras 5 códigos incorrectos el usuario queda bloqueado 5 minutos.
    - Desactivar: Ajustes → "Desactivar" (pide contraseña y un código).
    - ¿Perdió el celular? Un administrador entra a Usuarios → "Quitar 2FA";
      la persona vuelve a entrar solo con contraseña y puede reactivarla.
    También sirven Microsoft Authenticator, Authy, 2FAS, etc.

  EXPORTAR A EXCEL
    Botón "Exportar" (ícono ⬇) arriba a la derecha en Estudiantes, Materias,
    Docentes y Carreras (respeta el filtro de carrera elegido). En la planilla
    de notas: "Exportar planilla" (los inscriptos con su total, calificación
    y cada componente; el encabezado dice cuánto vale cada uno en esa
    materia). En Asistencia: "Planilla de asistencia" y "Habilitados para el
    final". En Inicio: "Exportar todas las notas". El estudiante
    tiene "Descargar en Excel" en Mis notas. Cada uno exporta SOLO lo que
    puede ver (un docente, solo sus carreras y materias).

  CARGA MASIVA POR EXCEL (solo admin)
    Sirve para cargar una carrera entera de una vez.
    1. Crear la carrera (Carreras → "+ Nueva carrera", con sus semestres).
    2. Carga masiva → elegir la carrera → "Descargar plantilla".
       El Excel trae:
         Instrucciones .. cómo completarlo.
         Docentes ....... nombre completo, usuario, contraseña inicial.
         Materias ....... filas YA PREPARADAS para cada semestre de la
                          carrera (ej.: 6 filas para el 1°, 6 para el 2°...):
                          completar código, nombre, créditos y elegir el
                          docente de la lista desplegable.
         Estudiantes .... nombre completo, matrícula, usuario, contraseña.
       Lo que ya está registrado aparece en GRIS (no hace falta tocarlo).
    3. Completar el Excel y guardarlo.
    4. Carga masiva → arrastrar el archivo (o hacer clic para elegirlo).
       El sistema REVISA TODO SIN GUARDAR y muestra:
         - cuántos docentes, materias y estudiantes se van a crear,
         - cuántas filas ya existían (se omiten),
         - los ERRORES con su hoja y número de fila (ej.: "Materias, fila
           12: Semestre debe ser un número entero de 1 a 4").
    5. Si hay errores: corregirlos en el Excel y volver a subirlo.
       Con UN solo error no se guarda NADA (nunca queda una carga a medias).
       Si no hay errores: "Confirmar e importar".
    La misma plantilla se puede volver a subir más adelante con filas nuevas:
    lo que ya existe se omite y solo se agrega lo nuevo.
    Cada usuario creado así debería cambiar su contraseña inicial en Ajustes.

  Los datos quedan guardados en la base de datos: al apagar y volver a
  iniciar el sistema, todo lo cargado sigue ahí.

3. QUÉ SE NECESITA TENER INSTALADO
--------------------------------------------------------------------------
  OBLIGATORIO
  - Java 21 (JDK)
      https://adoptium.net/temurin/releases/?version=21
      o en PowerShell:  winget install EclipseAdoptium.Temurin.21.JDK
      Al instalar, marcar "Set JAVA_HOME variable".

  - Docker Desktop (para la base de datos PostgreSQL)
      https://www.docker.com/products/docker-desktop/
      o en PowerShell:  winget install Docker.DockerDesktop
      Después de instalar: reiniciar la PC y ABRIR Docker Desktop antes
      de usar iniciar-todo.cmd (tiene que estar abierto, no solo instalado).
      Alternativa sin Docker: instalar PostgreSQL y crear la base
      "seguimiento_academico" con usuario "upe" y contraseña "upe".

  - Internet la primera vez (descarga ~150 MB de librerías).

  OPCIONAL
  - Git, para descargar y subir cambios: https://git-scm.com/download/win
  - VS Code con el "Extension Pack for Java" para editar el código.

  NO HACE FALTA instalar Maven: el proyecto trae mvnw.cmd que lo descarga
  solo.

Después de instalar cualquier cosa: cerrar TODAS las ventanas de VS Code y
de terminal y volver a abrirlas (si no, Windows no "ve" el programa nuevo).

4. ARCHIVOS DE LA CARPETA PRINCIPAL
--------------------------------------------------------------------------
  MENU.cmd                  Menú con todas las opciones (ver sección 2).
  iniciar-todo.cmd          Verifica, levanta la base de datos, arranca el
                            backend y abre la página en el navegador.
  comandos\                 Un .cmd por cada acción: iniciar/detener la base
                            o el backend, estado, probar API, tests, borrar
                            la base... (ver sección 2).
  scripts\                  El código (PowerShell) que ejecutan esos .cmd.
                            comun.ps1 tiene las funciones compartidas.

  GUIA-DEL-PROYECTO.txt     Este archivo.
  README.md                 Documentación técnica (se ve linda en GitHub).
  CONTRIBUTING.md           Reglas para trabajar en equipo (ramas, commits, PR).

  pom.xml                   "Receta" del proyecto para Maven: versión de Java
                            y lista de librerías (dependencias).
  mvnw / mvnw.cmd           Maven Wrapper: descarga y usa Maven sin instalarlo.
                            mvnw es para Linux/Mac, mvnw.cmd para Windows.
  .mvn\                     Configuración del Maven Wrapper (qué versión bajar).

  docker-compose.yml        Define el contenedor de PostgreSQL 16:
                            base "seguimiento_academico", usuario/clave upe/upe,
                            puerto 5432. Los datos se guardan en un volumen
                            "pgdata", así que no se pierden al apagar.
  .env.example              Ejemplo de variables de configuración. Se copia

5. EL CÓDIGO FUENTE, PARTE POR PARTE
--------------------------------------------------------------------------
Todo el código Java está en:
    src\main\java\py\edu\upe\hernandarias\

El proyecto está organizado en CAPAS. Cada carpeta (paquete) tiene un
trabajo distinto:

  SeguimientoAcademicoApplication.java
      Punto de entrada. Tiene el main() que arranca todo el servidor.

  controller\  -> RECIBE las peticiones HTTP y devuelve respuestas JSON.
                  No tiene lógica: solo llama al service.
      AuthController ............ login
      CalificacionController .... listar, registrar, modificar y eliminar notas
      AsistenciaController ...... clases (pasar lista), resumen por materia,
                                  reporte general y exoneraciones
      InscripcionController ..... inscribir / quitar estudiantes de materias
      EstudianteController ...... listar, crear, editar y eliminar estudiantes,
                                  y "mis notas" / "mi asistencia" del estudiante
      MateriaController ......... listar, crear, editar y eliminar materias, y
                                  cambiar sus PUNTAJES (PUT .../puntajes)
      CarreraController ......... listar, crear, editar y eliminar carreras
      DocenteController ......... listar, crear, editar y eliminar docentes
      UsuarioController ......... listar usuarios, crear administradores,
                                  activar/desactivar y cambiar contraseñas
      PerfilController .......... datos del usuario que inició sesión, sus
                                  preferencias de colores, su contraseña y
                                  la verificación en dos pasos

  service\     -> LÓGICA DE NEGOCIO: las reglas del sistema.
      PermisosService ........... LA JERARQUÍA: dice si alguien es ADMIN y
                                  en qué carreras tiene materias un docente.
                                  Los demás servicios lo usan para filtrar
                                  lo que ve cada docente y rechazar (403) lo
                                  que no le corresponde.
      PerfilService ............. Guarda las preferencias de apariencia,
                                  cambia la propia contraseña y activa /
                                  desactiva la verificación en dos pasos.
      AuthService ............... Comprueba usuario y contraseña y genera el
                                  token JWT. Si el usuario tiene 2FA, pide y
                                  verifica el código de 6 dígitos.
      CalificacionService ....... Registrar, modificar, eliminar y listar
                                  notas. Reglas: el DOCENTE solo opera en
                                  las materias que tiene a cargo (y solo ve
                                  esas notas); el estudiante tiene que ser de
                                  la carrera de la materia; una sola nota
                                  por estudiante y materia; cada componente
                                  no supera lo que vale en la materia; el
                                  examen final solo a quien está habilitado.
      AsistenciaService ......... Clases y asistencia, resumen por materia,
                                  reportes, alertas y exoneraciones (máximo
                                  2 por semestre).
      CalculoAsistencia ......... LA FÓRMULA del reglamento: porcentaje,
                                  3 tardanzas = 1 ausencia, faltas que
                                  quedan y condición (habilitado, en riesgo,
                                  no habilitado, exonerado).
      InscripcionService ........ Inscribe (uno por uno o la carrera entera)
                                  y no deja quitar a quien ya tiene
                                  asistencia o notas.
      EstudianteService ......... Crea el estudiante junto con su usuario
                                  (contraseña cifrada); no deja repetir
                                  matrícula ni usuario, ni borrar a quien
                                  tiene notas, ni cambiarlo de carrera si
                                  ya tiene notas. Un docente solo lista,
                                  crea y edita estudiantes de sus carreras.
      DocenteService ............ Crea el docente junto con su usuario; no
                                  deja borrar a quien tiene materias a cargo.
      MateriaService ............ Asigna carrera y docente; no deja repetir
                                  código ni borrar materias con notas.
                                  Cambia los PUNTAJES: tienen que sumar 100
                                  y no se achica una parte si alguna nota
                                  ya cargada la supera.
      CarreraService ............ No deja repetir código ni nombre, ni borrar
                                  carreras con materias o estudiantes.
      UsuarioService ............ Crea administradores; un admin no puede
                                  desactivarse a sí mismo.

  repository\  -> ACCESO A LA BASE DE DATOS. Son interfaces: Spring Data
                  JPA escribe el SQL automáticamente según el nombre del
                  método.
      UsuarioRepository, DocenteRepository, EstudianteRepository,
      CarreraRepository, MateriaRepository, CalificacionRepository,
      InscripcionRepository, ClaseRepository, AsistenciaRepository,
      ExoneracionRepository

  entity\      -> Clases que representan las TABLAS de la base de datos.
      Usuario ......... tabla usuarios (username, contraseña cifrada, rol,
                        preferencias de apariencia)
      Docente ......... tabla docentes (nombre completo; enlazado a su usuario)
      Estudiante ...... tabla estudiantes (matrícula, nombre, carrera)
      Carrera ......... tabla carreras (código, nombre, semestres,
                        asistencia mínima)
      Materia ......... tabla materias (código, nombre, créditos, semestre,
                        carrera, docente a cargo, asistencia mínima propia,

      Calificacion .... tabla calificaciones (nota total de 0 a 100, sus

6. CÓMO FUNCIONA POR DENTRO (EL RECORRIDO DE UNA PETICIÓN)
--------------------------------------------------------------------------
Ejemplo: un docente registra una nota.

  1. El docente hace login (POST /api/auth/login) y recibe un token.
  2. Envía POST /api/calificaciones con el token en el header.
  3. JwtAuthenticationFilter valida el token -> sabe que es "docente".
  4. SecurityConfig comprueba que el rol DOCENTE puede usar esa ruta.
  5. CalificacionController recibe el JSON y valida (valores entre 0 y 100).
  6. CalificacionService aplica las reglas (¿existe el estudiante? ¿la
     materia? ¿la materia es de ESTE docente? ¿el estudiante es de la
     carrera de la materia? ¿ya tiene nota? ¿algún parcial supera lo que
     vale en esa materia? si trae examen final, ¿está habilitado por
     asistencia?).
  7. CalificacionRepository guarda la nota en PostgreSQL.
  8. Se devuelve la nota creada como JSON con código 201 Created.
  Si algo falla en cualquier paso, GlobalExceptionHandler responde con el
  código de error adecuado.

Códigos de respuesta:
  200/201/204  todo bien
  400      datos inválidos (ej.: nota 150, un parcial de 16 cuando vale
           15, o puntajes que no suman 100)
  401      sin token, token vencido o contraseña incorrecta
  403      el rol no tiene permiso (ej.: estudiante registrando notas, o
           docente cargando notas en una materia que no es suya)
  404      no existe lo que se pide
  409      algo repetido (nota en la misma materia, matrícula, código,
           usuario), materia de otra carrera que la del estudiante, examen
           final a un estudiante no habilitado, achicar un puntaje que una
           nota ya supera, o se intenta borrar algo que está en uso

Probar a mano desde PowerShell (con la API iniciada):

  # Login del docente y guardar el token
  $r = Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/auth/login `
       -ContentType application/json -Body '{"username":"docente","password":"docente123"}'
  $h = @{ Authorization = "Bearer $($r.token)" }

  # Registrar nota
  Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/calificaciones -Headers $h `
       -ContentType application/json -Body '{"estudianteId":1,"materiaId":2,"nota":90}'

  # Modificar la nota con id 1
  Invoke-RestMethod -Method Patch -Uri http://localhost:8080/api/calificaciones/1 -Headers $h `
       -ContentType application/json -Body '{"nota":95}'

  # Nota desglosada (1er parcial, 2do parcial, TP y final)
  Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/calificaciones -Headers $h `
       -ContentType application/json `
       -Body '{"estudianteId":1,"materiaId":3,"primerParcial":12,"segundoParcial":14,"trabajoPractico":18}'

  # Cambiar los puntajes de la materia 2: parciales de 20, sin TP, final de 60
  Invoke-RestMethod -Method Put -Uri http://localhost:8080/api/materias/2/puntajes -Headers $h `
       -ContentType application/json `
       -Body '{"primerParcial":20,"segundoParcial":20,"trabajoPractico":0,"examenFinal":60}'

También se puede usar Postman, Insomnia o la extensión "REST Client" de
VS Code.

8. BASE DE DATOS
--------------------------------------------------------------------------
  carreras (id, codigo, nombre, semestres, asistencia_minima)
     |-- 1 a muchos -- estudiantes (id, usuario_id, matricula,
     |                              nombre_completo, carrera_id)
     |-- 1 a muchos -- materias (id, codigo, nombre, creditos, semestre,
                                 carrera_id, docente_id, asistencia_minima,
                                 clases_previstas, puntaje_primer_parcial,
                                 puntaje_segundo_parcial,
                                 puntaje_trabajo_practico,
                                 puntaje_examen_final)

  usuarios (id, username, password_hash, rol, activo)
     |-- 1 a 1 -- estudiantes.usuario_id
     |-- 1 a 1 -- docentes (id, usuario_id, nombre_completo)
                     |-- 1 a muchos -- materias.docente_id (docente a cargo)

  calificaciones (id, estudiante_id, materia_id, nota, primer_parcial,
                  segundo_parcial, trabajo_practico, examen_final,
                  fecha_registro, fecha_actualizacion)
  inscripciones  (id, estudiante_id, materia_id, fecha_registro)
  clases         (id, materia_id, fecha, tema)
     |-- 1 a muchos -- asistencias (id, clase_id, estudiante_id, estado,
                                    observacion)
  exoneraciones  (id, estudiante_id, materia_id, motivo, otorgada_por)

  Reglas: un estudiante tiene UNA sola nota por materia, la nota va de
  0 a 100, y solo puede tener notas de materias de su carrera. Los
  puntajes de cada materia suman 100 (la base lo controla con un CHECK) y
  el examen final vale al menos 1. Una sola clase por materia y día, y una
  sola asistencia por estudiante y clase. Las contraseñas se guardan
  cifradas (BCrypt), nunca en texto.

  Las tablas las crea y actualiza Flyway con los archivos de
  src\main\resources\db\migration (ver sección 5). Si alguien tenía la
  base de una versión anterior, al iniciar se convierte sola sin perder
  datos.

Comandos útiles (terminal en la carpeta del proyecto):
  docker compose up -d       levantar la base de datos
  docker compose stop        apagar la base (los datos se conservan)
  docker compose down -v     BORRAR la base por completo (se vuelve a
                             crear con los datos de ejemplo al iniciar)

9. TESTS
--------------------------------------------------------------------------
  Doble clic en comandos\ejecutar-tests.cmd, opción 8 del MENU.cmd,
  o en la terminal: .\mvnw.cmd test

  Comprueban, entre otras cosas, que:
  - el login devuelve un token y las contraseñas se guardan cifradas
  - se rechazan contraseñas incorrectas y usuarios inactivos
  - sin token se responde 401
  - un docente registra y modifica una nota y el estudiante la ve
  - un estudiante NO puede registrar notas (403)
  - una nota fuera de 0-100 da 400
  - una nota duplicada da 409
  - modificar una nota que no existe da 404
  - el admin gestiona carreras y docentes; el docente no puede
  - el admin asigna docentes a materias
  - el docente agrega y edita estudiantes SOLO de sus carreras (403 en
    otras), solo los ve a ellos, y no los elimina
  - un docente sin materias no ve carreras, materias ni estudiantes
  - cada usuario guarda sus colores; colores inválidos dan 400
  - cambiar la propia contraseña exige la actual
  - 2FA: activar con código, login que pide el código, código incorrecto,
    bloqueo tras 5 intentos, desactivar y "Quitar 2FA" del admin
  - Excel: cada uno exporta solo lo suyo; la plantilla trae filas por
    semestre; la carga valida, importa, no duplica al resubir y con un
    error no guarda nada
  - una materia no puede estar en un semestre mayor que la duración de
    su carrera
  - el docente SOLO califica sus materias (403 en las de otro docente o
    sin docente) y solo ve las notas de sus materias
  - no se pone nota de una materia de otra carrera (409)
  - no se repiten matrículas, códigos ni usuarios (409)
  - no se borran carreras, docentes, estudiantes ni materias en uso (409)
  - las notas se filtran por estudiante y por materia
  - un usuario desactivado ya no puede entrar
  - la página web se sirve sin necesidad de token
  - el docente inscribe estudiantes de la carrera en SUS materias
  - pasar lista, 3 tardanzas = 1 ausencia, la justificada cuenta como
    ausencia, y la condición para el final con y sin clases previstas
  - no se carga examen final a un estudiante no habilitado
  - exoneraciones: solo el admin, máximo 2 por semestre

11. CÓMO TRABAJAR EN EQUIPO CON GIT
--------------------------------------------------------------------------
  (detalle completo en CONTRIBUTING.md)

  Primera vez:
      git config --global user.name "Tu Nombre"
      git config --global user.email "tu_correo_de_github@ejemplo.com"

  Antes de empezar a trabajar (traer lo último):
      git switch main
      git pull
      git switch -c feature/nombre-de-lo-que-hago

  Guardar y subir cambios:
      git add .
      git commit -m "feat: descripción corta del cambio"
      git push -u origin feature/nombre-de-lo-que-hago

  Después, en GitHub, abrir un Pull Request hacia main. NUNCA trabajar
  directamente sobre main.
